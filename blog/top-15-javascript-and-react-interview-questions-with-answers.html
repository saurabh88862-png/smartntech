Top 15 JavaScript and React Interview Questions with Answers

Career• Oct 13, 2026• 9 min read

Closures, event loop, hoisting, hooks, virtual DOM and more, explained simply.

Front-end and full stack interviews cover JavaScript fundamentals and React concepts. Here are fifteen frequently asked questions with clear, interview-ready answers.

JavaScript

1. What is the difference between let, const and var?

var is function-scoped and hoisted with the value undefined. let and const are block-scoped and stay in a temporal dead zone until declared. const cannot be reassigned.

2. What is a closure?

A function that remembers variables from its outer scope even after the outer function has returned. Closures enable data privacy, callbacks, debouncing and memoization.

3. Explain the event loop.

JavaScript runs synchronous code on the call stack. Async callbacks wait in queues. When the stack is empty, all microtasks (Promise callbacks) run first, then one macrotask (such as a setTimeout callback), and the cycle repeats.

4. == vs ===?

== converts types before comparing, so 0 == '0' is true. === compares type and value without conversion. Prefer ===.

5. What is hoisting?

Declarations are processed before code runs. Function declarations are fully hoisted, var variables are hoisted as undefined, and let and const are hoisted but cannot be accessed before their declaration.

6. Explain this in JavaScript.

this depends on how a function is called: the object before the dot in a method call, undefined in strict-mode plain calls, and the new object with new. Arrow functions do not have their own this; they use the surrounding one.

7. What is the difference between null and undefined?

undefined means a value has not been assigned. null is an intentional "no value" set by the developer.

8. Promise.all vs Promise.allSettled?

Promise.all rejects as soon as any promise rejects. Promise.allSettled waits for all of them and reports each result, whether fulfilled or rejected.

React

9. What is the virtual DOM?

A lightweight JavaScript representation of the UI. When state changes, React creates a new tree, compares it with the previous one (reconciliation) and updates only the real DOM nodes that changed.

10. State vs props?

Props are read-only inputs passed from a parent. State is data a component manages itself; updating it triggers a re-render.

11. Why are keys important in lists?

Keys help React identify which items changed, were added or were removed. Stable unique ids prevent incorrect updates and unnecessary re-renders.

12. Explain useEffect and its dependency array.

useEffect runs side effects after render. With no array it runs after every render; with an empty array, once after mounting; with values, whenever those values change. A returned function performs cleanup.

13. What are controlled and uncontrolled components?

A controlled input's value comes from React state and updates through onChange. An uncontrolled input keeps its own value in the DOM, read with a ref.

14. How do you prevent unnecessary re-renders?

Keep state close to where it is used, wrap pure components in React.memo, stabilize props with useMemo and useCallback, and split large components. Measure with the React Profiler first.

15. What is prop drilling, and how do you avoid it?

Passing props through many intermediate components that do not need them. Solutions include component composition, the Context API, or state libraries such as Zustand or Redux Toolkit.

Final advice

Interviewers value clear explanations with small examples. For each answer, be ready to write a short code snippet and describe where you used the concept in your own projects.
